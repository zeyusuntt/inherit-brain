    How it works

    1. HERB records

      Slack messages, meeting transcripts, documents and pull requests, per product.

    2. Extraction

      Rules plus a model turn records into people, bugs, features, PRs and their links. Audited in six rounds.

    3. One graph per product

      herb:<product> on FalkorDB: 56,708 nodes and 164,698 edges over 30 products, 16 node labels, 24 edge types.

    4. Nine typed tools

      Each runs fixed, read-only Cypher. The model chooses the tool and fills its parameters, nothing else.

    5. Agent loop

      Connects as a read-only database user, at most 12 tool calls and 60,000 input tokens per question.

    Separate what-if tool (if_leaves): GRAPH.COPY of the product graph under its own ACL user. Not in the agent's tools and not part of the scored run; the If someone leaves page shows its output.

    The nine tools

    Calls are A5's tool calls over the 1,203 held-out questions. bridges was available and never called.

    • resolve_personA name to employee ids; namesakes all returned, flagged ambiguous.22 calls
    • resolve_entityA document, customer, PR, bug, feature or competitor name to node ids, full-text fallback.608 calls
    • doc_peopleAuthors and key reviewers of a document type, with role and evidence.361 calls
    • bug_boardBugs counted by company or person, by status, optionally as of a date.399 calls
    • fix_trailCustomer, its bugs, the PRs that fix them, and the PR authors.90 calls
    • feature_fateFeatures by fate, with dated history, contributors and PRs.226 calls
    • who_saidTyped observations about competitors and releases, and demo links.226 calls
    • pr_boardProduct PRs by approval, merge, revert reason and kind, or their authors.234 calls
    • bridgesPeople ranked by betweenness on the collaboration graph.0 calls

    The graph schema

    Node and edge counts are totals over the 30 product graphs (FalkorDB 6.0.2). Each edge count is the type's total over all its endpoints; the drawing shows its main endpoints. HAS_EVENT (6,576) links bugs and features to their event histories. DISCUSSES also links meetings to features and documents, and messages to documents; REPORTED_BY also links observations to customers and people. Endpoints follow src/inherit/ontology.py.

    FalkorDB features doing work

    Counts come from A5's 8,104 recorded queries in the held-out run. Tested on FalkorDB 4.22.1 and 6.0.2. Features that no held-out question needed are listed with their zero.

    • A graph per productherb:<product>, one per product; the agent only ever sees one.
    • Read-only ACL userOne per product for the agent. All 8,104 queries ran as GRAPH.RO_QUERY.
    • Full-text indexdb.idx.fulltext.queryNodes, the fallback inside resolve_entity: 88 queries.
    • User-defined functionherb_v1.statusAt returns a bug's status on any date, for bug_board(as_of=...): 0 queries; no held-out question asked for a past date.
    • Betweennessalgo.betweenness for knowledge bridges (native on 6.0.2, computed in Python on 4.22.1): 0 queries.
    • Vector indexesBuilt at load on message and document embeddings. None of the nine tools queries them: 0 queries.
    • GRAPH.COPYThe what-if counterfactual, on a copy, under a separate ACL user. Not scored.

      Run it yourself

      Python with uv, FalkorDB 4.22.1 and 6.0.2 in Docker. The test suite runs the tools against both servers. The raw HERB data is not in the repository.

      Setup in the README Every tool's Cypher MCP server over the same tools 

      $ uv sync
$ docker compose up -d
$ uv run pytest -q
